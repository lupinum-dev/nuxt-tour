# Implementation plan

Each slice must leave the repository buildable and must not expose options for a
later slice early.

## 1. Definition and controller kernel

Implement literal-preserving definitions, validation, application-scoped
registry, linear navigation, conditions, transition locking, aborts, cleanup,
events, and typed errors. Use fake route and target adapters in focused tests.

Acceptance: the controller journeys in the runtime specification pass without a
DOM or Nuxt application.

## 2. Vue runtime and semantic targets

Implement `createTourPlugin()`, `useTour()`, `useTourTarget()`, attribute lookup,
bounded waiting, and effect-scope cleanup. Add the `/vue` export only when the
packed consumer proves it.

Acceptance: a plain Vue fixture completes a same-page target tour and leaves no
listeners or observers after end and failure.

## 3. Accessible host

Implement `TourHost`, `TourContent`, one spotlight, default card, full-card slot,
focus behavior, interaction modes, structural CSS, and reduced motion. Add
Floating UI in this slice because this is the first code that uses it.

Acceptance: keyboard, focus, geometry, scrolling, and custom-card browser tests
pass.

## 4. Nuxt-native integration

Register the Vue runtime, router adapter, auto-imports, components, and CSS.
Discover `app/tours/**/*.ts`. Generate the registry and application-specific
tour and step ID declarations. Support development updates without restarting
when practical.

Acceptance: the README quick start builds without runtime imports, IDs
autocomplete, invalid IDs fail type checking, and cross-route tours pass.

## 5. Documentation and release candidate

Replace proposal language with verified user documentation. Make docs and a
clean external fixture consume the packed tarball. Complete the browser matrix,
package-size check, accessibility review, and launch checklist.

Acceptance: `pnpm release:verify` passes for the exact candidate and all
remaining external or human launch gates are recorded in one GitHub issue.

## Open decisions

These decisions belong to their implementation slice and do not block the
foundation:

- the exact default target timeout and missing behavior;
- whether `cancel(reason)` accepts a free string or a typed application reason;
- the minimum public CSS variable set;
- the exact generated type augmentation mechanism; and
- the browser support matrix beyond the last two evergreen releases.

Do not resolve these by adding configuration. Use tests and one real consumer
journey to choose the smallest contract.
