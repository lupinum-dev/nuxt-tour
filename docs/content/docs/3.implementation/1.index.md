# Implementation plan

The runtime slices are implemented. Each remains independently testable and
does not expose options owned by another layer.

## 1. Definition and controller kernel

Implemented: literal-preserving definitions, validation, application-scoped
registry, linear navigation, conditions, transition locking, aborts, cleanup,
events, and typed errors. Use fake route and target adapters in focused tests.

Acceptance: the controller journeys in the runtime specification pass without a
DOM or Nuxt application.

## 2. Vue runtime and semantic targets

Implemented: `createTourPlugin()`, `useTour()`, `useTourTarget()`, attribute lookup,
bounded waiting, and effect-scope cleanup. Add the `/vue` export only when the
packed consumer proves it.

Acceptance: a plain Vue fixture completes a same-page target tour and leaves no
listeners or observers after end and failure.

## 3. Accessible host

Implemented: `TourHost`, `TourContent`, one spotlight, default card, full-card slot,
focus behavior, interaction modes, structural CSS, and reduced motion. Add
Floating UI in this slice because this is the first code that uses it.

Acceptance: keyboard, focus, geometry, scrolling, and custom-card browser tests
pass.

## 4. Nuxt-native integration

Implemented: the Vue runtime, router adapter, auto-imports, components, and CSS.
Discover `app/tours/**/*.ts`. Generate the registry and application-specific
tour and step ID declarations. Support development updates without restarting
when practical.

Acceptance: the README quick start builds without runtime imports, IDs
autocomplete, invalid IDs fail type checking, and cross-route tours pass.

## 5. Documentation and release candidate

Current release-candidate work: verified user documentation, a clean packed
consumer, package-size review, and the browser matrix.

The release gate runs lint, type checking, unit and Nuxt integration tests, the
module and documentation builds, and a clean Nuxt build installed from the
packed tarball. A Chromium browser pass covers the cross-route journey,
keyboard focus, modal cleanup, browser Back, and console errors. Firefox and
WebKit remain first-stable-release gates.

Acceptance: `pnpm release:verify` passes for the exact candidate and all
remaining external or human launch gates are recorded in one GitHub issue.

## Frozen version 1 decisions

- Target waiting defaults to 5000 ms and missing targets fail.
- `cancel(reason)` accepts an application-owned string.
- The default theme exposes only the CSS variables used by the shipped card and
  follows system, class-based, or `data-theme` light/dark modes.
- Nuxt augments `TourRegistry` from direct definition imports.
- Nuxt 4 and Vue 3.3 or newer are the supported framework floor.
